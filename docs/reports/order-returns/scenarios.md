### Scenario 1: Amazon return with specific item name
- **Category:** happy_path
- **Prompt:** "I need to return the wireless headphones I bought on Amazon last week"
- **Expected outcome:** The agent navigates to the Amazon orders page, locates the wireless headphones order, and reaches the return initiation screen where a return reason can be selected.
- **Success criteria:**
  1. Safari opens to the Amazon orders page without the user having to navigate manually
  2. The correct order containing "wireless headphones" is identified and selected (not a different order)
  3. The return flow is initiated and a return reason selection screen or return confirmation is visible
- **Notes:** This is the most common real-world scenario — a user remembers what they bought and which store it came from. Tests basic skill matching on "return" + "Amazon" keywords and the item parameter extraction from natural language.

### Scenario 2: Walmart return with vague item description
- **Category:** happy_path
- **Prompt:** "Return that Walmart order, the blue shirt"
- **Expected outcome:** The agent opens the Walmart orders page, finds an order containing a blue shirt, and begins the return process.
- **Success criteria:**
  1. The agent navigates directly to walmart.com/orders (using the skill's direct URL, not searching through the Walmart homepage)
  2. The agent visually identifies an order matching "blue shirt" even if the order listing says something like "Men's Cotton Crew Neck T-Shirt — Blue"
  3. The "Start a return" or equivalent button is clicked and the return reason page is reached
- **Notes:** Tests fuzzy item matching — users rarely remember the exact product title. The phrase "that Walmart order" is casual and tests whether the skill triggers on informal phrasing. Also tests whether the agent handles Walmart's login gate if it appears.

### Scenario 3: Target return for a gift
- **Category:** happy_path
- **Prompt:** "I want to return a baby blanket I got from Target, it was the wrong size"
- **Expected outcome:** The agent opens the Target orders page, locates the baby blanket order, and navigates through the return flow including selecting a return reason related to sizing.
- **Success criteria:**
  1. Safari opens to target.com/orders
  2. The baby blanket order is found and its details page is opened
  3. The return flow reaches the reason selection step, and a size-related reason (e.g., "Too small", "Too large", "Wrong size") is selected or at least the reason selection page is displayed
- **Notes:** The user is providing a reason embedded in the prompt ("wrong size"). Tests whether the agent can carry contextual information forward into later steps of the return flow, not just match the item.

### Scenario 4: Ambiguous retailer — user just says "return"
- **Category:** ambiguous_input
- **Prompt:** "Can you return the coffee maker I ordered? I think it was like $40"
- **Expected outcome:** The agent either asks the user which retailer the order was from, or attempts to check the most likely retailer (Amazon as default) and searches for a coffee maker around $40.
- **Success criteria:**
  1. The agent does not crash or silently pick a random retailer without any signal — it either asks for clarification or makes a reasonable default choice
  2. If the agent picks a retailer, it navigates to that retailer's orders page and searches for "coffee maker"
  3. The price hint ("like $40") is not ignored — if multiple coffee maker orders exist, the agent uses the price to disambiguate
- **Notes:** Real users often forget where they ordered something. This tests the system's behavior when no retailer keyword is present. The price hint tests whether non-standard context from the prompt is used during the visual search phase. There are three return skills available — the system needs a strategy for when none is a clear match.

### Scenario 5: Item not found in order history
- **Category:** error_recovery
- **Prompt:** "Return the running shoes from my Amazon orders"
- **Expected outcome:** The agent navigates to the Amazon orders page, searches for running shoes, and when no matching order is found, reports back to the user that the item could not be located rather than clicking on an unrelated order.
- **Success criteria:**
  1. The agent opens the Amazon orders page and visually scans for "running shoes"
  2. The agent does NOT click on an unrelated order (e.g., a book or electronics item) just to continue the flow
  3. The agent reports failure clearly — something like "Could not find running shoes in your recent orders" — and does not loop indefinitely retrying the same page
- **Notes:** This is critical for trust. A real user who asks to return shoes does not want the agent to start returning their laptop instead. Tests the infeasibility detection and error recovery path documented in the skill templates ("If no orders match: report to user that item was not found"). Also tests that the frustration score mechanism triggers appropriately when the agent cannot make progress.
