**Findings**
1. `P0` Scroll-based recovery can advance the plan without ever completing the original interaction. In [_handle_failure](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3558), a missing-target retry can become a bare `scroll` via [_vary_strategy](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3683), and any successful scroll is treated as recovery of the original `click`/`type_text`. Separately, [_scroll_recovery](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L2872) dispatches the original action but returns a synthetic success without normal postcondition verification, while the main loop has already recorded the original failure at [_execute](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L472). User-visible effect: the agent can scroll once, skip the intended click, and continue on a false success; the trace then records the wrong outcome. Fix: remove the bare `scroll_down_and_retry` strategy now that `_scroll_recovery` exists, and make scroll recovery return a fully verified replacement result that replaces the earlier failure in `step_results`.

2. `P0` Replans lose almost all of the hardening that was added to initial planning. The initial path applies fallback replacement, truncated-plan detection, navigation enforcement, and `click` `on_fail` normalization in [_execute](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L331), but the replan path in [_replan_and_continue](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3813) only reinjects domain verification. The prompt is weaker too: the initial prompt has the e-commerce completion and skill-depth rules in [plan_from_prompt.md](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/planner/prompts/plan_from_prompt.md#L57), while [replan_from_state.md](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/planner/prompts/replan_from_state.md#L44) omits them. User-visible effect: after the first failure, replans can regress to trivial `done`, navigation-only, or otherwise shallow plans. Fix: factor plan hardening into one shared helper used by both `plan` and `replan`, and port the missing prompt rules into the replan prompt.

3. `P1` Promotion is blocked whenever the current run yields zero new observations, even though the librarian explicitly evaluates the full stored history. [_maybe_promote_skill](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L4058) returns early on empty `observations`, but [_evaluate_run_inner](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/skills/librarian.py#L133) immediately reloads `all_observations` from disk and makes decisions from that corpus. The current test suite even codifies the no-op behavior in [test_skill_librarian_integration.py](/Users/jagatp/workspace/macos-automation-agent/tests/unit/test_skill_librarian_integration.py#L495). User-visible effect: once a skill has enough accumulated evidence, promotion still will not fire unless the latest run also distilled something new. Fix: call `promote_from_run` whenever `skill_name` exists, and let the librarian decide whether the stored groups qualify.

4. `P1` Tier-1 verification has real matcher bugs beyond the known click fallthrough. In [_verify_tier1](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/verifier.py#L441), `open_url` passes when `actual_lower in expected_lower`, so landing on a site homepage can incorrectly satisfy a deeper target URL. In the same method for `type_text` at [_verify_tier1](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/verifier.py#L462), the verifier returns `False` on the first populated field that does not match, instead of checking all available fields. User-visible effect: the agent can continue from the wrong page, or retry/replan even though text entry succeeded. Fix: require same host plus actual URL/path compatibility for navigation, and make text verification succeed if any populated state field matches, only failing if none do.

5. `P2` The tests leave the highest-risk execute-loop behavior underprotected. The old orchestrator suite is entirely skipped in [test_agent.py](/Users/jagatp/workspace/macos-automation-agent/tests/orchestrator/test_agent.py#L15), and newer absence tests explicitly patch around scroll-first recovery in [test_element_absence.py](/Users/jagatp/workspace/macos-automation-agent/tests/unit/test_element_absence.py#L81). There is no direct execute-level regression test for “replan gets the same hardening as initial plan” or “scroll recovery replaces the recorded failure with a verified success.” Fix: add execute-loop tests for those exact cases before changing the code, because the current suite can stay green while these regressions persist.
