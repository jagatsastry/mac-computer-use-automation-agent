## Findings

### P0-1: DerivedSkillSession.serialize_for_context() drops current_steps
- **Location:** `derived_skill.py:31,82`, `agent.py:3792,4013`
- **Description:** `apply_patch()` updates `current_steps`, but `serialize_for_context()` never emits it. The planner and distiller only ever see the serialized form, so the "current best step sequence" never actually leaves memory.
- **Evidence:** `apply_patch()` updates `current_steps`; both replan and distiller paths rebuild context from `serialize_for_context()`, which omits that field entirely.
- **Fix:** Serialize `current_steps` explicitly, then add an end-to-end test asserting patched steps appear in replan and distiller context.

### P0-2: Librarian groups by (category, category) instead of (category, recommendation)
- **Location:** `librarian.py:301,178`, `experience.py:91,122`
- **Description:** The librarian groups observations by category only and records promotion keys as `(category, category)`, not `(category, recommendation)`. That merges unrelated observations into one promotion candidate and prevents `mark_promoted()` from matching.
- **Evidence:** `_group_observations()` builds `groups[(cat, cat)]`; `mark_promoted()` and `top_for_context()` key by normalized `(category, recommendation)`.
- **Fix:** Group and persist by normalized recommendation, not category echoing, and add tests with multiple recommendations in the same category.

### P0-3: Promotion writes ignore registry's configured skill_dir
- **Location:** `librarian.py:613,668,857`, `registry.py:77`
- **Description:** Promotion writes hardcode `src/automation_agent/skills/library`. With a custom `skill_dir`, `patch_parent` can write history and mark promoted without persisting the skill file, and `create_sibling` writes into the wrong library.
- **Evidence:** `SkillRegistryImpl` supports custom `skill_dir`; librarian helpers never use it. `_commit_patch_parent()` still succeeds when `_find_skill_path()` returns `None`.
- **Fix:** Resolve promotion paths from the registry's configured skill directory and fail promotion if the canonical file cannot be updated on disk.

### P0-4: Duplicate Walmart stub files shadow canonical skill
- **Location:** `return_walmart_order.md`, `return-walmart-order.md`, `return-walmart-order-2.md`, `registry.py:186`
- **Description:** Two promoted Walmart stub files shadow the canonical skill at runtime. Causes test failure blocking the entire unit test suite.
- **Evidence:** `git ls-files -- src/automation_agent/skills/library/*walmart*` returns all three files. `test_no_duplicate_walmart_skill_files` fails, blocking remaining 174 tests.
- **Fix:** Remove tracked stub files, add CI guard for duplicate skill names, stop tests/promotions from writing into checked-in library.

### P1-5: Malformed derived_skill_patch creates empty ReplanPatch instead of None
- **Location:** `planner.py:434`, `agent.py:3834`
- **Description:** Bad patch output is treated as a real patch object instead of being skipped. Violates AC-9.
- **Evidence:** AC-9 says malformed patch data must be skipped as `None`; current parser returns empty `ReplanPatch()` instead.
- **Fix:** Return `None` when patch payload is absent or unusable, update parser/orchestrator tests.

### P1-6: create_sibling validation too weak for stated contract
- **Location:** `librarian.py:513`, `loader.py:89`
- **Description:** Generated sibling missing `summary`, `tags`, `## Error Recovery`, or `## Notes` can still pass validation.
- **Evidence:** `_validate_sibling_md()` only checks parse success, `trigger_keywords`, `steps_text`, `success_condition`, and `parent-skill-id`.
- **Fix:** Validate full sibling schema, add negative tests for each required field/section.
