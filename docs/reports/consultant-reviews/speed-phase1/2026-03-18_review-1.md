**Findings**
1. Severity: `P1`. Location: [applescript_actuator.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/actuator/applescript_actuator.py#L62), [applescript_actuator.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/actuator/applescript_actuator.py#L78). Description: `AppleScriptActuator.click()` now unconditionally calls `_activate_browser()` before every click. If the agent is automating Calculator, Finder, System Settings, etc. while any browser is merely running, focus is stolen to that browser and the click lands in the wrong app; when no browser is frontmost, this code actively picks one anyway. Recommended Fix: make focus restoration app-aware, not browser-aware; only reactivate a browser when the current step is explicitly a browser step or when the pre-click state says the target app is already a browser.

2. Severity: `P1`. Location: [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L928), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L967), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L1112), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L4902). Description: the new success-condition gate does not actually gate completion. On failure it `pop()`s the `done` result and `break`s out of the step loop, but execution then falls through to the normal success return path; it also uses `iterations < infeasibility_replan_limit` instead of replan count, and the replan execution path never checks `success_condition` at all. Recommended Fix: convert “success condition failed” into an explicit replan/failure state, key the guard off replan count, and run the same gate in `_replan_and_continue()` before accepting any `done`.

3. Severity: `P1`. Location: [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L492), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L801), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L1218), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L1348), [status.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/status.py#L81). Description: the run-report / verbose-overlay paths persist raw step params, full URLs, state changes, and truncated raw LLM responses even though `_redact_params_for_log()` already exists for confirmation logs. That means typed secrets, passwords, and query-string tokens can be written to `report.md`, `events.jsonl`, `trace.md`, and shown in the overlay. Recommended Fix: route all report/overlay/log payloads through a shared redaction layer; redact `text`/credential fields, strip or whitelist URL query params, and never persist raw planner responses unless explicitly opted in.

4. Severity: `P1`. Location: [grounding_router.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/grounding_router.py#L110), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3168), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3295). Description: keyboard-shortcut dispatch is keyed only off the element description, not the active app. `click "address bar"` or `type_text(..., element="search bar")` will issue `Cmd+L` globally even when no browser is frontmost; in the `type_text` path the `press_key()` result is not even checked before typing continues. Recommended Fix: require a verified browser context before returning `keyboard_shortcut`, fall back to normal grounding otherwise, and check shortcut execution success in both click and type-to-focus flows.

5. Severity: `P2`. Location: [config.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/config.py#L545), [planner.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/planner/planner.py#L134), [planner.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/planner/planner.py#L276), [coordinator.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/vision/coordinator.py#L287), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L1201). Description: `resolve_step_model()` returns `(provider, model)`, but the resolved model is discarded by both planner and vision callers, which still use `self.config.openai_model` / `gemini_model` / `anthropic_model`. Malformed override strings are also unvalidated, so typos silently fall through to inconsistent defaults, and run reports record the global provider/model rather than the one actually used. Recommended Fix: validate override syntax/provider names at config load, thread the resolved model into provider-specific call helpers, and record the actual provider/model at each call site.

Location: [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L1307), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3104), [agent.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/orchestrator/agent.py#L3430), [event_logger.py](/Users/jagatp/workspace/macos-automation-agent/src/automation_agent/logging/event_logger.py#L104).
